# Local Kind deployment

This directory contains Kubernetes manifests for running Crystal Code Quest on a
local Kind cluster. The cluster is single-node and uses SQLite, so the
application runs with **one replica** and a **PersistentVolumeClaim** for the
database.

## Cluster details

The existing local cluster is Podman-backed and named `ai-lab`. The current
kubectl context is `kind-ai-lab`.

## Build and load the image

```bash
export IMAGE_TAG="crystal-code-quest:$(git rev-parse --short HEAD)"
podman build -t "$IMAGE_TAG" .
kind load docker-image "$IMAGE_TAG" --name ai-lab
```

`kustomization.yaml` pins the image tag to the current Git short SHA. Update it
with the same command before applying if the commit changes:

```bash
(cd infrastructure/kind && kustomize edit set image crystal-code-quest="$IMAGE_TAG")
```

## Create the session secret

The application requires a `SESSION_SECRET` environment variable. Create a Secret
from the local `.env.local` file (generated by `pnpm db:setup`):

```bash
kubectl create secret generic crystal-code-quest \
  --from-literal=session-secret="$(grep '^SESSION_SECRET=' .env.local | cut -d '=' -f2)" \
  --namespace crystal-code-quest
```

Alternatively, use `secret.example.yaml` as a template.

## Apply the manifests

```bash
kubectl apply -k infrastructure/kind
```

## Wait for rollout and verify

```bash
kubectl rollout status deployment/crystal-code-quest -n crystal-code-quest
kubectl port-forward -n crystal-code-quest svc/crystal-code-quest 3000:3000
```

In another terminal:

```bash
curl -s http://localhost:3000/api/health | jq
```

## View logs

```bash
kubectl logs -n crystal-code-quest deployment/crystal-code-quest
```

## Clean up only this application

```bash
kubectl delete -k infrastructure/kind
kubectl delete secret crystal-code-quest -n crystal-code-quest
```

This removes the Crystal Code Quest deployment but leaves the Kind cluster
intact.
